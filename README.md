# leaf

Лёгкий self-hosted планировщик с видимой иерархией задач. Целевой первый релиз включает Гант, зависимости и пересчитываемый критический путь.

**Сейчас реализованы S0–S3 и отдельные задачи S4:** локальный вход, сохраняемое дерево, Гант, параметры плана в компактной правой панели и визуальная схема зависимостей. Сервер пересчитывает рабочие календари, критические пути, резервы и конфликты; изменения атомарны и отменяются целиком. **Это промежуточный этап, не готовая V1:** повседневный UX/доска, restore/import/export и релизная приёмка остаются S4–S6.

**Демо:** https://leaf-sua8.onrender.com/ — общий синтетический пример на Render Free. Он сбрасывается при каждом перезапуске, а после простоя просыпается около минуты. Не вводите личные данные.

### Что уже работает

- Проекты с деревом задач произвольной глубины. У проекта две вкладки: «Задачи» (дерево и Гант) и «Журнал».
- Необязательные начало, окончание и длительность. Рабочий календарь и часовой пояс задаются в настройках проекта.
- Гант с переносом и изменением длины полосы мышью и клавиатурой.
- FS-зависимости между конечными задачами и их визуальная схема.
- Серверный пересчёт критического пути, резервов и конфликтов сроков; атомарная отмена изменений плана.
- Журнал работы: датированные записи по задачам.

Пока нет: доски и остального повседневного UX (S4), восстановления, импорта и экспорта (S5), релизной приёмки (S6).

Картинки в [design/](design/README.md) — концепт-макеты, не скриншоты приложения. Вкладок «Календарь», «Файлы» и «Заметки», нарисованных на главном макете, в leaf нет: они вне scope ([PROJECT](docs/PROJECT.md)).

## Локальный запуск

Нужны Node 24.21.0, npm 11.19.0, Python 3 и make для reviewed native install. Runtime storage хранится вне checkout. Используйте отдельные синтетические данные для разработки.

```sh
make install
make build
make admin-setup
make dev
```

Make использует `LEAF_DATA_DIR` из окружения или аргументов; по умолчанию — `~/.local/share/leaf-dev` вне репозитория. Например, `make dev LEAF_DATA_DIR=/var/tmp/leaf-development`. При выборе другого каталога передавайте его также в `admin-setup`, `start` и команды БД. Повторный запуск — `make dev`; настройка аккаунта нужна только один раз на базу.

Откройте http://127.0.0.1:5173. Настройка аккаунта требует интерактивный терминал, скрытый ввод и подтверждение пароля; default account и удалённого setup нет. API работает на loopback:3000; `LEAF_PORT` меняет серверный порт и Vite proxy; `LEAF_DEV_PORT` меняет порт Vite и его origin по умолчанию. `make start` обслуживает собранную SPA и API на http://127.0.0.1:3000; origin по умолчанию соответствует серверному порту. Если `LEAF_PUBLIC_ORIGIN` задан в окружении, он должен совпадать с адресом браузера. Ctrl+C (SIGINT) или SIGTERM останавливают приложение.

`make` или `make help` показывает все команды. Makefile вызывает существующие npm-скрипты; прямой запуск через npm описан в [BOOTSTRAP](docs/BOOTSTRAP.md).

| Команда | Действие |
|---|---|
| `make install` / `make build` | Установка зависимостей / сборка |
| `make admin-setup` | Интерактивная настройка аккаунта после сборки |
| `make admin-reset-password` | Сборка и локальная смена пароля с сохранением задач |
| `make dev` / `make start` | Разработка / запуск собранного приложения |
| `make verify` | Typecheck, lint, unit/integration tests и сборка |
| `make test-unit` / `make test-integration` | Отдельные группы тестов |
| `make install-browser` / `make test-e2e` | Установка Chromium / сборка и браузерные тесты |
| `make format-check` / `make check-package` | Форматирование / границы Docker-пакета |
| `make db-migrate` / `make db-backup BACKUP=/var/tmp/leaf-backups/new-snapshot.sqlite` | Миграции / резервная копия после сборки |
| `make doctor` / `make preflight` | Среда / kit и privacy проверки |

Production-контейнер, локальные Docker команды и режим публичного синтетического демо описаны в [DEPLOYMENT](docs/DEPLOYMENT.md). `render.yaml` описывает один Free Docker Web Service с ручным deploy; владелец разместил по нему демо, адрес указан выше. Демо общее для посетителей и сбрасывается при каждом запуске сервера: не вводите личные данные. Реальная контейнерная проверка прежней упаковки выполнена на Linux ARM64; результат проверки обновлённого образа указан в STATUS.

Если пароль не подходит, остановите `make dev` через Ctrl+C, выполните `make admin-reset-password`, введите новый пароль дважды и снова запустите `make dev`. Используйте тот же `LEAF_DATA_DIR`, что при запуске приложения. Проекты и задачи сохраняются; старые сеансы и история отмены очищаются. Команда требует локальный интерактивный терминал и не принимает пароль в аргументах или переменных окружения. Для прямого npm-запуска после сборки: `npm run admin:reset-password` с явно заданным `LEAF_DATA_DIR`.

## Необязательные сроки

В панели задачи начало, включительное окончание и длительность независимы и необязательны. Изменение одного поля не заполняет остальные. Полная пара должна быть допустима для календаря; заданная длительность должна совпадать с её рабочим интервалом. Перед изменением сроков завершённую задачу явно возвращают в работу. Настройки проекта содержат календарь и часовой пояс для линии «Сегодня».

Гант сохраняет общие строки с деревом. Полная реальная пара даёт обычную полосу; неполная сводная задача остаётся без полосы. Условная приглушённая полоса использует серверную проекцию и не становится исходными датами. Одиночные исходные даты показаны отдельными отметками. Перенос меняет обе границы, resize — окончание; при несовпадении заданной длительности требуется явный выбор синхронизации или очистки. Клавиши ←/→ и Shift+←/→ дают те же действия, Esc отменяет жест.

«Зависимости» показывает непосредственных предшественников и последователей отдельными стрелками. FS разрешены только между конечными задачами одного проекта; иерархия не создаёт precedence. Доказанный конфликт сроков сопровождается диагностикой. По C16 сервер анализирует введённые интервалы: в ready показывает критические задачи, только тесные critical FS-связи и отдельные резервы проекта/текущего размещения. Incomplete оставляет общий путь неизвестным и отдельно подписывает анализ полностью датированных компонент до известного горизонта; infeasible подавляет critical styles. Сводный индикатор отражает критических конечных потомков. Historical pending response подписан «Сохранённый результат без расчёта критического пути» и не пересчитывается. Финальная Task7 адаптация ещё проходит независимый review/root gate. Первый релиз ещё не готов.

## Журнал работы

«Журнал» проекта и четвёртая вкладка панели показывают одни и те же датированные текстовые записи. Запись можно добавить к любой задаче, включая родителя, завершённую и работу без сроков, из общего меню строки или редактора проекта. Дата — отдельный календарный день; журнал не меняет статус, сроки, зависимости или CPM. Поиск учитывает текст и текущее название задачи; период включительный, страницы догружаются кнопкой «Показать ещё».

Черновики и состояние посещений живут только в RAM текущей сессии. Закрытие редактора сохраняет черновик; reload теряет его и требует подтверждения при незавершённой работе. Редактор и подтверждение удаления сохраняют исходную revision при фоне и повторном открытии; конфликт разрешается явно. После потери ответа доступен точный повтор прежней операции. Пока её исход неизвестен, другие записи, отмена и переходы блокируются. Успешный выход или401 очищает приватное состояние.

«Отменить изменение плана» относится к плану. Удалённая запись не восстанавливается этой кнопкой; удаление ветки захватывает записи для ограниченного plan Undo. Более поздние записи задачи блокируют отмену её создания. Подробности — [спецификация/D21](docs/superpowers/specs/2026-10-10-task-journal-design.md). Будущий S5 export/import должен включить активный журнал; публичный формат ещё не реализован.

## API и совместимость

Журнал использует GET `/api/projects/:id/journal`, GET `/api/projects/:id/tasks/:taskId/journal`, GET/PATCH/DELETE `/api/projects/:id/journal/:entryId` и POST `/api/projects/:id/journal`. Его strict DTO/envelopes содержат `journalContractVersion: 1`, отдельные `expectedJournalRevision`/UUID `operationId`; транспортный header остаётся2. Journal CRUD/replay обходятся без пересчёта планировщика.

Все project routes требуют `X-Leaf-Contract-Version: 2` после входа. Команды и rename содержат `contractVersion: 2`, `expectedRevision` и UUID `operationId`. Ответы дерева/расписания также версионированы. `task.edit` сохраняет текст, статус и source patch атомарно; пропущенное поле сохраняет значение, `null` очищает его. `project.schedule` меняет только календарь/часовой пояс. Отмена восстанавливает весь snapshot.

Неверсионированный клиент получает HTTP 426 с просьбой обновить страницу до доступа к проекту. Для точного повтора прежней операции target-aware клиент добавляет `X-Leaf-Legacy-Replay: 1`, сохраняя original body. Это только lookup ранее сохранённого результата; неизвестный запрос не выполняется. Повтор сохраняет прежнюю ревизию ответа даже после новых изменений.

Свежая база применяет 001→002→003→004; schema3 получает аддитивную004, schema4 переоткрывается без DDL. Существующая schema2 требует backup, readonly preview и явного подтверждения digest; обычный startup её не меняет. Schema1 отклоняется до промежуточной миграции. Миграция003 сохраняет аккаунт, операции и undo, архивируя original legacy данные server-only. Процедура — [BOOTSTRAP](docs/BOOTSTRAP.md) и [DEPLOYMENT](docs/DEPLOYMENT.md). Production migration, публикация и deployment агентом не выполнялись.

## Проверки

```sh
npm run verify
npm run format:check
npm run check:package
npm exec playwright -- install --with-deps chromium
npm run test:e2e
```

`verify` запускает typecheck, lint, настоящие unit/integration tests и build. E2E использует собранный сервер, собственные временные синтетические SQLite-базы и реальные перезапуски процессов. Снимки остаются вне checkout, traces/video выключены. Kit/privacy проверки выполняются отдельно:

```sh
npm run check:kit
npm run test:kit
npm run doctor
npm run preflight
```

Preflight требует Git, Gitleaks и установленные hooks; подготовка — в [BOOTSTRAP](docs/BOOTSTRAP.md). Он проверяет безопасность репозитория и комплект, а не поведение приложения.

## Хранение

```sh
npm run db:migrate
npm run db:backup -- /var/tmp/leaf-backups/new-snapshot.sqlite
```

Обе команды используют `LEAF_DATA_DIR`. Backup создаёт согласованный snapshot SQLite через native API, включая актуальный WAL, и отказывает при существующем destination. Файл содержит аккаунт, задачи, активный журнал, journal state/replay и приватный sidecar отмены удалённых записей; он приватный. Restore и проектный JSON import/export ещё не реализованы (S5).
