# Интерфейс

Приоритет: [три изображения](../design/README.md) → выбранная компоновка → эти правила → детали реализации. Семантика данных и безопасность всегда выше декоративных деталей рисунка.

## Главное окно

Узкая спокойная боковая навигация с leaf, проектами, архивом и настройками. Без дашборда KPI, карточек метрик и лишних разделов. Вверху — проект, поиск и минимальные действия. На первой версии достаточно «Задачи / Доска / Настройки»; включение Ганта — переключатель представления задач.

Дерево примерно 380–520 px в зависимости от viewport, рядом временная шкала; разделитель можно двигать. У строки круг статуса, раскрывающая стрелка у родителей, название, компактная дата. Произвольные технические номера и отдельные колонки длительности/исполнителя не обязательны.

Иерархия читается отступами 20–24 px, сворачиванием и более заметным названием родителя. Не превращать экран в плотную spreadsheet-таблицу. Критичность не кодировать кругом статуса: это разные признаки.

**Общий flattened visible-tree** строится один раз для дерева и Ганта. Одинаковые высоты и порядок строк, синхронная вертикальная прокрутка. Нельзя отдельно сортировать правую и левую части. Раскрытие/фильтр меняют только отображение.

Время горизонтально прокручивается независимо от дерева. На Ганте тонкая сетка, мягкий фон выходных, линия сегодня. Summary-полоса — отличимая сводная форма; обычная работа — полоса; задача без дат — пустая строка; одна дата — отметка, а не выдуманная веха длительностью 0.

## Правая панель

Компактная панель ~360–400 px, поверх правого края без затемнения остального экрана. Параметры начальные, агент сверяет с референсом. Заголовок и закрытие закреплены; содержимое прокручивается. Esc закрывает панель, если не открыт внутренний popover, и возвращает фокус к строке. На узком экране допустим overlay большей ширины.

Вкладки первого релиза: **Детали / Подзадачи / Зависимости**. «Комментарии» и другие необязательные элементы из рисунка скрыты до отдельного решения. Не открывать второй sidebar поверх первого при переходе по задаче — заменить выбранную задачу и сохранить доступ к возврату.

Детали: название, статус, начало/окончание/длительность, режим планирования, «не раньше», необязательный дедлайн, описание, компактное вычисленное состояние критичности/резерва. Значения, полученные расчётом, отличимы от пользовательских ограничений. Сводные даты не редактируются как собственная работа.

Подзадачи: переиспользовать основной компонент дерева и быстрый ввод. **Отдельный дизайн не выбран. Последний коллаж не использовать.**

## Выбранная схема зависимостей

Компактная вертикальная схема непосредственных соседей: карточки предшественников → текущая задача → карточки последователей. Это граф зависимостей, не дерево вложенности.

Все независимые предшественники соединяются **отдельными стрелками с текущей задачей**. Не рисовать их цепочкой только ради размещения. Аналогично последователи получают собственную входящую связь. Название, короткий диапазон дат или «Не запланировано», статус. Критическая связь — отдельное вычисленное выделение плюс доступная текстовая подпись.

Добавление через поиск только допустимых конечных задач того же проекта. Запрещены текущая задача, дубль, summary-задача и связь, создающая цикл. Ошибка объясняет цепочку. Удаляется связь, не задача. «Показать на Ганте» выделяет строку и прокручивает временную шкалу.

Для множества соседей: прокрутка/«Показать ещё» внутри секции, выбранная задача видна. Вспомогательный расширенный вид допустим без нового обязательного глобального граф-редактора. Не добавлять React Flow только ради пяти карточек.

## Доска

Это запланированная функция без утверждённого скриншота. Рабочее предложение: раскрываемые вложенные группы родителей проходят через колонки «К выполнению / В работе / Готово», карточки конечных работ размещаются по статусу. Родитель — заголовок, не дублирующая карточка. Не скрывать вложенность ради простого Kanban.

Перетаскивание между статусами не меняет родителя, даты или связи. Отмена работает. Сначала прототип на синтетических данных для проверки владельцем в S4; не копировать отвергнутые варианты.

## Состояния и доступность

Нужны пустой проект, пустая вкладка, загрузка, ошибка сохранения, offline-соединение с сервером, цикл, конфликт дат, неполный расчёт, удалённая выбранная задача. Не показывать зелёное «Сохранено» до подтверждения сервера.

Клавиатурный фокус заметен. Семантические кнопки и подписи, доступное дерево, сохранение фокуса при удалении, клавиатурная альтернатива drag-and-drop. Tab перехватывать только в явно активном редакторе дерева; не ломать навигацию формы. Цвет дополняется текстом/иконкой; проверять контраст, особенно pastel-текст.

Прогресс родителя считается по конечным подзадачам; пользователь должен понимать знаменатель. На свёрнутой критической ветви — небольшой индикатор «Внутри критические задачи». Красным не закрашивать все summary-задачи автоматически.

## Визуальная приёмка

При 1440×900 и 1280×800 сравнить структуру с референсами: sidebar, плотность строк, доли дерева/Ганта, вес заголовков, компактность панели. Снимки для тестов только на синтетическом проекте. Не обещать pixel-perfect для генеративного макета с неточными надписями и датами. Нужна честная рабочая реализация, а не похожая статичная картинка.
