# Приёмка leaf V1

Каждому критерию нужен тест или воспроизводимая ручная проверка с синтетическими данными. Служебный `check:kit` не заменяет ни один application test.

Адаптация C11–C15 имеет отдельные [критерии OS01–OS17 и независимые примеры](superpowers/specs/2026-10-07-optional-scheduling-design.md). Они задают уточнённую приёмку до последующей синхронизации CPM после O06. Исторические Auto-числа A08–A11/A14 и соответствующие fixtures остаются примерами S2–S3, а не утверждением алгоритма по явным датам. Полная V1 по C05 требует закрытия G-CPM и нового численного набора; документальное ревью не заменяет этого решения.

## Дополнительные автоматические свойства

Для целевой модели: исходные nullable поля не заполняются условным display; FS проверяется по реальным границам без автосдвигов; duration и календарная длина согласованы по явной политике. Summary охватывает всех конечных потомков только при полностью определимом интервале, иначе обе даты null. Collapse/filter не меняют реальные данные и knownStartMin группы; одинаковый вход даёт одинаковый результат; undo возвращает исходную проекцию данных по содержимому (номер revision может увеличиться); ошибка транзакции ничего не меняет. Математические свойства float/critical IDs определяются после G-CPM; старые Auto-свойства не являются новым контрактом.

Для calendar-тестов обязательно проверить конец месяца/года, високосный февраль и даты перехода DST, даже если интерфейс работает только с днями. Для export/import проверить HTML/script как обычный текст, обход путей и ссылки на чужой проект.

## Минимальные наборы тестов после S0

Domain unit + property tests, SQLite integration, API auth/validation/transaction tests, React interaction tests, Playwright E2E и визуальный smoke. `npm test` не должен запускать только kit tests и считаться полным тестированием leaf.
