# C25 — размещение задач при установке FS-связи

Дата: 2026-10-08. Подтверждённое требование владельца: при установке связи начало зависимой задачи должно быть строго после включительного окончания предшественника; раннюю дату необходимо перенести. Задачи без начала и окончания также отображаются с учётом зависимостей. Документ уточняет [C24](2026-10-08-fs-dependencies-design.md) и [C19](2026-10-08-conditional-gantt-design.md). Остальные правила C16/C17/D17 сохраняются.

## 1. Реальные сроки при добавлении связи

Нижняя граница начала — следующий рабочий день после максимального достоверного окончания всех входящих предшественников. Равенство с включительным окончанием тоже требует переноса. Позднее начало сохраняется. При полном интервале сдвигаются обе даты с сохранением количества рабочих дней и точного nullable duration; start-only переносит только начало. Отсутствующие даты не назначаются.

Все способы добавления связи используют серверный каскад: task.create с predecessorIds, relation-only task.edit, dependency.create и task.edit, одновременно изменяющий сроки и добавляющий входящее ребро. Последний случай заменяет прежний отказ C24 §3.3: сервер принимает введённый валидный интервал и возвращает канонический перенесённый интервал. Подтверждение сохранения обновляет поля карточки и её clean baseline. Каскад downstream, summary/CPM, revision, retry и undo остаются одной транзакцией.

Если в task.edit не добавлено входящее ребро этой задачи, прямое изменение сроков, нарушающее существующую FS-связь, по-прежнему отклоняется. Повтор прежних endpoints не является добавлением. Новый предшественник с неизвестным окончанием не отменяет известные ограничения остальных. Done, invalid/unavailable интервалы, cycle и реальное переполнение сохраняют существующие отказы и полный rollback. Нет обхода проверки исходных полей.

## 2. Условная геометрия бездатных задач

**Рабочий D18:** меняется только отображение конечных задач, у которых обе даты null. Базовая опора C19 — минимум исходных начал родительской группы, иначе сегодня в timezone проекта. Начало условной полосы — максимум базовой опоры и следующих рабочих дней после доступных окончаний всех входящих предшественников. Если базовой опоры нет, известная зависимость сама даёт условную опору. Окончание полосы использует duration либо один display-день.

Для геометрии предшественника используется валидный реальный интервал, иначе допустимая условная полоса C19/C25. Поэтому цепочка полностью бездатных работ последовательно размещается после каждого условного окончания. Fan-in берёт максимум, diamond не суммирует сдвиги. Работа с одиночной исходной датой сохраняет собственную опору C19; полные реальные интервалы также не передвигаются отображением. Summary, invalid/unavailable full pair и unsaved draft не создают условных bounds. Иерархия не создаёт FS.

Чистый dependency-display helper обходит полный граф итеративно за O(V+E), до фильтра/сворачивания. Today передаётся извне: сервер использует null, браузер — дату проекта. Клиент пересчитывает весь display от исходных own/group опор, а не от ранее смещённого schedule.display; смена дня в обе стороны не оставляет устаревший anchor. Для этого helper принимает задачи, связи, calendar, реальные проекции и базовые C19-полосы. Групповые опоры вычисляются по исходным началам, условные сдвиги не меняют их.

Невалидный граф не запускает размещение по циклу. При отсутствии поддерживаемого дня после 9999-12-31 условная полоса ограничивается этим днём с clipped=true; её последователи также помечаются clipped. Это видимое ограничение геометрии, не доказательство FS и не ошибка записи бездатной работы. Исходная duration сохраняется.

Условные значения не записываются в tasks, не входят в реальный FS/CPM/coverage/summary. Nullable исходные поля и подпись «Условное размещение; полный интервал не задан», пунктирные полосы/стрелки сохраняются. Reveal, initial window, today refresh и рисунок используют одну проекцию полного графа. Drag/resize условной полосы не записывают даты.

## 3. Приёмка

| ID | Сценарий | Результат |
|---|---|---|
| L01 | A заканчивается 09.10.2026 (пятница), B начинается 09.10; новая связь, weekdays | B начинается 12.10; обе даты полной пары сдвинуты с сохранением span/null duration |
| L02 | В карточке одновременно поменять валидные сроки B и добавить A | Успех, канонические даты в карточке; один revision/undo, exact retry без повторного переноса |
| L03 | B уже позже границы; несколько предшественников | Поздняя дата сохранена; ранняя переносится после максимума достоверных окончаний |
| L04 | B без дат, duration=2; A заканчивается в пятницу 09.10; weekdays, today=08.10, без групповой опоры | Условно B=12–13.10; source даты null, unknown precedence/CPM не подменены геометрией |
| L05 | A→B→C без дат, today=09.10 (weekdays), duration=null | A=09.10, B=12.10, C=13.10; сегодня=08.10 даёт 08,09,12.10 без записи/revision |
| L06 | Fan-in/diamond, другая ветка дерева, filter/collapse | Максимум входящих display finishes; полная проекция сохраняет позиции видимых работ |
| L07 | Одиночные даты, invalid/unavailable pair, summary, draft | Собственные опоры и прежние ограничения сохраняются; нет выдуманных реальных bounds |
| L08 | Завершённая работа, цикл, overflow реального push; отдельный source edit без новой связи | Прежние атомарные отказы; ошибка не меняет данные, outcome, undo и revision |
| L09 | Условный overflow, today refresh, reveal и клавиатура | Clipped пояснение, корректная видимая дата; условные интервалы не редактируются жестом |

## 4. Объём

Без изменения DTO/SQL/migrations, новых библиотек, автопланирования реальных дат, lag, календарей праздников или новой компоновки. Только синтетические fixtures. Скриншот владельца и его тексты не сохраняются. Состояние S4–S6 не меняется этой задачей.
