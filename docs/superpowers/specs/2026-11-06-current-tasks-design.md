# «Актуальное» — задачи текущего проекта по срочности

Дата: 2026-11-06. Статус: спецификация выбранного владельцем дизайна; реализация ещё не выполнена.

## 1. Цель и решения

Помочь выбрать следующую работу, не просматривая всё дерево: отдельная вкладка **Задачи · Актуальное · Журнал** в текущем проекте.
Дерево и Гант остаются во вкладке «Задачи», карточка задачи — существующей компактной панелью справа.

**C32, подтверждено владельцем:** отдельное представление «Актуальное», простой дизайн с наиболее срочными задачами сверху и группами «Просрочено → Сегодня → Скоро → Позже → Без окончания».
**D24, рабочие детали:** вкладка текущего проекта между «Задачи» и «Журнал», незавершённые конечные задачи, реальные `inputFinish` по возрастанию; порог трёх рабочих дней, правила границ, раскрытия, строк и навигации ниже. Это не новые поля или настройки продукта.
Сохраняются [C15/C19](../../DECISIONS.md), [правила панели](../../UI.md) и [три PNG](../../../design/README.md); дополнительный утверждённый PNG не появляется.

## 2. Данные и срочность — D24

Источник — последний принятый серверный `ProjectTree` текущего проекта, до любых фильтров/сворачивания дерева.
Конечная задача не имеет детей в полном snapshot; включаются только `todo` и `doing`.
Сводные задачи и `done` не образуют строк; завершённость родителя сама по себе не исключает незавершённого ребёнка.
Отсутствие начала/длительности не мешает использовать заданное `task.inputFinish`.
При `inputFinish = null` задача попадает в «Без окончания», даже если начало и длительность или условная полоса позволяют нарисовать окончание.
Не использовать summary, CPM, зависимости, conditional Gantt dates или draft-поля для срочности.

`today` — текущая календарная дата в `project.timezone`, без переноса на рабочий день.
Окончание включительно: задача с окончанием сегодня ещё не просрочена.
Граница `soonEnd` — третий рабочий день **строго после today** по `project.calendarType` (`weekdays` / `all-days`).
Сегодня в эти три дня не входит; на выходном отсчёт начинается с ближайшего следующего рабочего дня.
Это фиксированный порог первой версии, без настройки пользователя.

| Группа | Условие для сохранённого окончания `finish` |
|---|---|
| Просрочено | `finish < today` |
| Сегодня | `finish = today` |
| Скоро | `today < finish <= soonEnd` |
| Позже | `finish > soonEnd` |
| Без окончания | `finish = null` |

Сравниваются календарные даты, не UTC-моменты. Если snapshot содержит окончание на нерабочий день, оно сравнивается как есть; UI его не округляет и не исправляет.
На верхней границе допустимого диапазона дат `soonEnd` ограничивается последней допустимой датой; представление не падает и ничего не записывает.
Внутри датированной группы сортировка по `inputFinish` по возрастанию: самые старые просрочки первые.
При одинаковом окончании и в «Без окончания» — полный порядок дерева: preorder, siblings по `sortOrder`, затем `id`, как в существующем tree helper.
Результат не зависит от исходного порядка массива, состояния раскрытия дерева или совпадения названий.

## 3. Компоновка и действия — D24

Светлое рабочее пространство leaf, мягкие разделители и компактные строки вместо карточек/метрик.
Шапка сохраняет название проекта и общую отмену плана; ниже — три вкладки в указанном порядке.
Status popover, quick add и controls Ганта относятся только к «Задачам», controls журнала — только к «Журналу».
Уточнение владельца 2026-11-07 добавляет отдельное поле «Поиск задач» в шапку «Актуального» по образцу Ганта. Рабочие детали: поиск по подстроке названия с теми же NFC/регистром/trim, только по незавершённым конечным задачам; пути сохраняются. Счётчики отражают совпадения, новый запрос раскрывает группы, очистка восстанавливает обычное сворачивание. Нет совпадений — отдельное состояние. Крестик/Escape очищают ввод с сохранением фокуса. Запрос независим от фильтров дерева, сохраняется в RAM visits при смене вкладок и Back/Forward, сбрасывается при новом проекте/reload/logout. Данные плана и открытая карточка от поиска не меняются. Подробности — [UI](../../UI.md).

Все пять заголовков групп видимы, включая нулевые, с количеством входящих задач независимо от раскрытия.
При первом открытии проекта «Просрочено», «Сегодня», «Скоро» раскрыты; «Позже» и «Без окончания» свёрнуты.
Заголовок — кнопка с `aria-expanded` и связанной областью; клик, Enter и Space переключают раскрытие.
Раскрытая пустая группа содержит короткую подпись «Нет задач»; при отсутствии всех кандидатов показывается общее «Нет незавершённых конечных задач».
Выбор раскрытия сохраняется в RAM для текущего проекта при переключении вкладок/карточки и обновлении snapshot; reload начинает с defaults.
Список показывает все строки раскрытых групп: без пагинации, «Загрузить ещё» и искусственного лимита.

Строка содержит индикатор статуса с доступной подписью, название, путь предков от корня до непосредственного родителя, ясную дату/срочность.
Для корневой работы вместо пустого пути — «Корень проекта»; путь текстовый, не набор новых действий.
Полное название/путь доступны при сокращении, в том числе с клавиатуры; одинаковые названия различаются контекстом.
Дата имеет явную подпись «Окончание: ДД.ММ.ГГГГ»; для просрочки добавляется «Просрочено», для сегодня — «Сегодня», для null — «Без окончания».
Срочность не передаётся одним цветом и не называется дедлайном или критическим путём.
Клик или Enter/Space по доступной с клавиатуры строке открывает эту задачу в существующей правой панели, вкладка «Задача».
Индикатор статуса не является checkbox; быстрых status/journal actions, меню строки и редактирования сроков прямо в списке нет.
Статус, сроки, зависимости, записи и другие действия доступны через существующую карточку и её commands.
При узком viewport действует существующее полноэкранное поведение карточки; список не добавляет горизонтального переполнения из-за длинных строк.

## 4. Обновления и состояния — D24

Представление — чистая клиентская проекция: входы snapshot, calendar, today; записей или пересчётов scheduler при открытии нет.
Статус и сроки меняют строку только после authoritative server acknowledgement/принятия нового snapshot.
После сохранения `done` строка исчезает, после Undo возвращается в актуальную группу и позицию; заголовки/counts обновляются вместе со строками.
Если задача получила детей, стала конечной, перенесена или переименована, состав/путь обновляются из полного принятого дерева.
Открытая карточка не закрывается из-за исчезновения строки, перемещения между группами или сворачивания группы; её черновики сохраняются.
Удаление самой задачи использует существующее поведение панели и защиты черновиков.
Ошибка записи/409/неопределённый исход не подменяются успехом; остаются штатные error, refresh и exact retry, без обхода locks.

Переиспользуется `useProjectToday`: смена дня отражается без reload не позднее следующей минутной проверки, также при focus/visibility return.
Подтверждённое изменение calendar/timezone немедленно пересчитывает группы; не создаёт дополнительную mutation, не сбрасывает раскрытие или draft.
Смена дня сама по себе не меняет source fields, project revision, историю Undo и URL.
Начальная загрузка показывает состояние загрузки проекта, а не пустой результат; при ошибке чтения — штатную ошибку и повтор загрузки.
При смене проекта чужие строки не выдаются за новый проект; прежний согласованный snapshot при ошибке refresh явно остаётся прежним.

## 5. Навигация и фокус — D24

Расширить существующий `ProjectView` значением `current`; URL: `?project=<id>&view=current`, прежние `task`/`panel` сохраняют смысл.
Без `view` остаётся «Задачи»; старые ссылки tasks/journal и проверка доступности project ID работают как прежде.
Direct link, reload и Back/Forward открывают нужное представление и существующую задачу независимо от её попадания в список.
Ссылка на done/summary может открыть карточку, но не добавляет ложную строку в «Актуальное»; отсутствующая задача следует существующему fallback.
Обычная смена представления сохраняет ту же смонтированную карточку и черновики, без нового запроса Save/Discard.
Существующие dirty guards применяются при смене/закрытии контекста задачи, проекта или редактора и защищаемом Back/Forward; pending/uncertain locks и правила journal drafts сохраняются.
В этих защищаемых переходах Сохранить/Не сохранять/Продолжить редактирование действуют до перехода; отказ не меняет URL, активную вкладку или фокус.
У tabs сохраняются roving tabindex, ArrowLeft/Right с циклическим переходом, Home/End; фокус переходит только при принятой навигации.
Существующие дерево/Гант/журнал сохраняют фильтры, раскрытие, draft и scroll при посещении «Актуального».
Раскрытие и позиция прокрутки «Актуального» входят в существующее RAM-состояние visit для Back/Forward; search/collapse в URL не добавляются.
При смене проекта — defaults нового проекта; история может восстановить посещённое состояние, но данные всегда берутся из актуального snapshot.
При возврате из карточки фокус получает исходная видимая строка; если она исчезла/свёрнута — заголовок исходной группы, затем активная вкладка.
Для direct link без строки-источника fallback — активная вкладка «Актуальное». Скрытое дерево/quick add не получают фокус.
Если сфокусированная строка исчезла при обновлении, применяется тот же fallback; обновление в фоне не перехватывает фокус из другого контрола.
Undo сохраняет штатный фокус кнопки, пока она доступна; при её отключении fallback принадлежит активному представлению, без фокуса в hidden tree.
Поздний ответ/отложенное восстановление не забирает фокус после самостоятельного перехода пользователя.
«Показать на Ганте» в карточке явно переводит в «Задачи», раскрывает путь и снимает фильтры по D14; обычное закрытие карточки этого не делает.

## 6. Приёмка на синтетических данных

| ID | Сценарий и ожидаемый результат |
|---|---|
| A01 | Глубокое дерево, свёрнутые родители, todo/doing/done и summary: ровно все незавершённые leaves; путь полный, родительский done не скрывает ребёнка. |
| A02 | `today=2026-11-06`, weekdays: 05.11 — «Просрочено», 06.11 — «Сегодня», 09–11.11 — «Скоро», 12.11 — «Позже», null — «Без окончания»; third-day boundary включена. |
| A03 | Для той же пятницы all-days даёт границу 09.11; для субботы 07.11/weekdays — 11.11. Сегодня на выходном остаётся сегодня; предельная дата не вызывает исключения. |
| A04 | Finish-only попадает по окончанию; start-only/duration-only/без дат остаются «Без окончания» независимо от conditional Gantt и сроков родителей. |
| A05 | Несколько просрочек: самые старые первые; равные даты и null следуют preorder/sortOrder/id даже при перемешанном входном массиве. |
| A06 | Defaults раскрытия, ручное сворачивание, counts, нулевые группы и полностью пустой список; больше обычной высоты экрана, все строки достижимы без load-more. |
| A07 | Строка открывает штатную карточку; ack done скрывает строку, не закрывая карточку; Undo возвращает её. Изменение finish переносит группу, создание ребёнка исключает бывший leaf. |
| A08 | Ошибка/409/uncertain save сохраняют draft и штатный retry; строка не выдаёт несохранённые поля за подтверждённые. Смена вида с той же карточкой не требует Save/Discard; уход из защищаемого task context можно отменить или продолжить после Save/Discard. |
| A09 | Смена даты в timezone проекта при открытом/возвращённом окне, затем смена календаря/timezone: группы обновлены, revision/Undo не меняются от одного тика. |
| A10 | Direct link/reload/Back/Forward для current с task/panel; done/summary/missing task и недоступный project; старые tasks/journal URL остаются рабочими. |
| A11 | Переключения трёх вкладок сохраняют контекст; фильтр дерева «только done» не влияет на «Актуальное»; возврат на Гант выполняет D14 лишь явным действием. |
| A12 | Только клавиатурой: три tabs, группы, строки, карточка/закрытие; исчезнувшая или свёрнутая строка и последний Undo не уводят фокус в hidden tree; поздний ack не крадёт фокус. |
| A13 | Загрузка, ошибка чтения и повтор, смена проекта: нет ложной пустоты/чужих строк. Длинные названия/пути и панель проверены в 1440×900, 1280×800 и узком viewport. |

Ожидаются независимые unit fixtures классификации/порядка, client tests навигации/ошибок/фокуса и actual-server browser checks ключевых сценариев.
После реализации: typecheck/lint/unit/integration, relevant E2E, format и documentation checks; фактические результаты — в STATUS, не в статусе этой спецификации.

## 7. Границы

Нет общего списка всех проектов, новых deadline/priority полей, настройки горизонта, status filters, quick actions, пагинации, доски или новой навигационной подсистемы.
Схема хранения, серверный интерфейс и правила расчёта расписания, критических путей и зависимостей остаются прежними. Состав пакетов, эксплуатационные правила и защита приватных данных не меняются; записи выполняются существующими серверными транзакциями.
Эта доработка не завершает S4–S6 и не является разрешением на push, публикацию или deployment.
