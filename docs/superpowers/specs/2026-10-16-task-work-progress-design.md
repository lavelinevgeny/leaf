# Ход работы: компактные записи в карточке задачи

Дата: 2026-10-16. Статус: реализовано по поручению владельца; evidence W01–W10 — в [ACCEPTANCE](../../ACCEPTANCE.md), общие проверки и ограничения — в [STATUS](../../STATUS.md).

## 1. Цель и границы

Пользователь быстро фиксирует сделанное, полученную информацию и препятствия, затем просматривает записи по дням. Во вкладке задачи «Журнал» заменить название на «Ход работы», сократить форму добавления и показывать длинные записи компактно.

Основание: [D21/D22](../../DECISIONS.md), [интерфейс](../../UI.md), [журнал задач](2026-10-10-task-journal-design.md), [карточка задачи](2026-10-15-task-panel-ux-design.md). Это уточнение представления существующих записей. Авторизация охватывает спецификацию, план и реализацию без дополнительной остановки между этапами.

Меняются только вкладка задачи и её composer/предпросмотр. Представление проекта по-прежнему называется «Журнал» и использует существующую полную ленту и форму. Обе ленты показывают одни серверные записи. Внутренние journal identifiers, URL `panel=journal`, API, схема, scheduler, CPM, FS и Undo плана сохраняются. Три выбранных PNG остаются утверждёнными референсами; присланный эскиз задаёт только рассматриваемые идеи. Вложения, вкладка «Файлы», аватары, исполнители, время и автоматическая история изменений исключены из объёма.

## 2. Названия и форма добавления

Три вкладки карточки: «Задача / Зависимости / Ход работы». Подсказка ввода остаётся «Что сделали или узнали по задаче?». Пустое состояние: «Записей пока нет». Вспомогательные технические сообщения могут сохранять слово «журнал», обозначающее хранилище записей.

Composer новой записи задачи — единый компактный блок. Textarea начинается с двух строк, расширяется при вводе, вставке и изменении доступной ширины. Полный черновик доступен через основную прокрутку панели, без отдельного постоянного скролла textarea. Форма не обрезает введённый текст. Явные переносы и пробелы в draft сохраняются.

Дата видима как DD.MM.YYYY, редактируется существующим CalendarDateInput с календарём. Видимая отдельная подпись «Дата записи» скрыта только в компактном composer; доступное имя остаётся. Сегодня определяется существующим механизмом timezone проекта. Явно выбранная или очищенная дата не заменяется автоматически. Дата и непустой текст остаются обязательными на уровне существующего контракта; дата предзаполнена, дополнительных обязательных полей нет.

Кнопка сохранения — компактная иконка с доступным именем и подсказкой «Сохранить запись», показывается после появления ввода, как существующие idle actions. Справа от текста располагаются дата и кнопка, когда ширины достаточно; в узком контейнере они переносятся под поле, сохраняя полезную ширину ввода. Кнопка «Очистить черновик» появляется для изменённого draft. Счётчик/инструкция могут быть скрыты визуально при обычном вводе; ошибка пустой/неверной даты и превышения существующего лимита 10000 UTF-16 code units остаётся видимой и доступной. Ошибки, retry и конфликт не сворачиваются в иконки.

Enter — перенос строки; Ctrl/Cmd+Enter — сохранение. Сочетание не отправляет текст во время IME composition. После подтверждённого сохранения действует существующий возврат фокуса в composer. Пустая/невалидная форма не создаёт запись. Редактирование существующей записи остаётся полным существующим редактором с текстовыми действиями.

## 3. Предпросмотр и полный текст

Только в ленте задачи каждая запись первоначально занимает не более четырёх визуальных строк текста. Длинные слова и URL переносятся в пределах панели. Переполнение определяется фактической раскладкой, пересчитывается после изменения текста, ширины, шрифта, открытия вкладки и browser zoom.

Для предпросмотра:

- убрать крайние пустые строки;
- последовательность пустых строк между абзацами сократить до одной пустой строки;
- пустой считать строку, состоящую из пробелов/табуляции; непустые строки, их отступы и переносы не переписывать;
- поддержать LF и CRLF, не изменяя сохранённый body.

«Показать полностью» появляется при визуальном переполнении **либо при отличии предпросмотра от оригинала**. Это обеспечивает доступ к исходному форматированию даже у короткого нормализованного текста. После раскрытия выводится исходный plain text целиком с `white-space: pre-wrap`; действие меняется на «Свернуть». Для короткого неизменённого текста действия нет. HTML и ссылки не интерпретируются.

Раскрытие выполняется внутри записи без modal, API-запроса или изменения draft. Состояние независимо для каждого entry ID, не сбрасывается при обычном refresh списка. Для новой выбранной задачи устанавливается исходное свёрнутое состояние. Во время редактирования показан исходный полный текст; действие раскрытия не мешает меню `⋯`. Семантическая кнопка имеет aria-expanded/aria-controls и доступна с клавиатуры.

## 4. Хронология и сохранность

Существующие группы по workDate, порядок `workDate DESC, createdAt DESC, id DESC`, keyset pagination и восстановление scroll anchor сохраняются. Запись задним числом попадает в соответствующую группу; редактирование body не превращается в новую дату работы. Просмотр/раскрытие не принуждает пользователя к началу списка. Между днями сохраняется заметный интервал; уплотнение прежде всего достигается короткой формой, четырьмя строками и нормализацией пустоты.

RAM-черновики изолированы по проекту/задаче. Переключение вкладок, dirty task draft, background refresh, 401/logout, stale revision и uncertain write следуют D21/D22. Не сбрасывать введённый текст при ошибке; неопределённый результат повторяется тем же envelope, подтверждённое сохранение с failed GET повторяет чтение. Нормализация — исключительно представление, не содержимое запросов и БД.
