# Направленный выбор связей и симметричный граф

Дата: 2026-11-07. Статус: спецификация порученной владельцем доработки C33; технические детали D28. Доработка реализована; фактическая приёмка и текущий цикл исправлений финального review отражены в [STATUS](../../STATUS.md). Владелец разрешил последовательные этапы спецификации, плана и реализации с независимым review; повторное согласование дизайна не требуется.

## 1. Объём и приоритет

Владелец выбрал два связанных изменения: симметричные секции предшественников/последователей внутри графа панели и компактный выбор направления связи из строки существующей задачи либо быстрого ввода. Обе стороны связи доступны в обоих контекстах. У существующей задачи можно добавлять и удалять связи; у новой они сохраняются вместе с созданием. В строках остаётся видимое количество сохранённых связей.

C33 заменяет запрет цепочки в строке от 2026-10-09 и дополняет C30 третьим действием. Используется общий `TaskTree`: основной список, левая часть Ганта, дерево подзадач. Существующий picker полосы Ганта переиспользует тот же выбор направления; новых жестов нет. «Актуальное», журнал, доска и общая перестройка панели вне объёма.

Сохраняются C08, C18, C19, C24/C25, D22 и [правила scheduling](../../SCHEDULING.md): только leaf FS, иерархия не является зависимостью, сроки необязательны, сервер выполняет каскад и CPM. «Перед» не назначает начало текущей задачи обратным расчётом от последователя. Новых типов связей, lag, drag-connect, библиотек, SQL-полей или миграции нет.

Просмотрены только три утверждённых PNG из [design/README](../../../design/README.md): светлое дерево, компактная правая панель, вертикальный граф. Новых image assets нет. В графе каждая стрелка соответствует конкретному ребру; случайные связи рисунка не воспроизводятся. Исключённый макет подзадач не используется.

## 3. Выбор семантики записи

Рабочий D28 сохраняет различие уже существующих способов записи. Универсальная немедленная запись в графе потеряла бы совместное сохранение сроков и входящих C25. Единый двусторонний черновик всей карточки потребовал бы расширить `task.edit`, scoped saves и конфликтные baseline без продуктовой необходимости. Поэтому общий picker разделяет представление и выбор направления, а хозяин сохраняет прежний способ записи.

| Вход | Направления | Добавление / удаление | Закрытие и отмена |
|---|---|---|---|
| Цепочка строки / полосы Ганта | «После» и «Перед» | Одна `dependency.create/delete` на действие, после server ack; глобальный Undo возвращает ребро и все вызванные изменения сроков. | После ack picker закрывается. Escape до/во время ожидания закрывает только слой, не отменяет отправленную команду. |
| QuickAdd основного дерева / подзадач | «После» и «Перед» | Меняет только свой полный RAM draft; создание одной `task.create` сохраняет обе группы связей. | Picker остаётся открыт для нескольких выборов; Escape/крестик сохраняют выбранное в QuickAdd. Отмена всего QuickAdd следует прежним правилам, очищая обе группы. |
| Граф, «Предшественники» | Фиксированное incoming | Добавление/удаление меняет общий incoming draft панели; Save либо «Готово» сроков отправляет одну `task.edit` со сроками и incoming. | Закрытие picker сохраняет draft. Отмена общего черновика восстанавливает baseline. |
| Граф, «Последователи» | Фиксированное outgoing | Existing immediate command; только при чистой панели. | Добавление закрывает picker после ack; удаление обновляет доступный список после ack, не закрывая его. Undo общий. |

Это симметрия внешнего вида графа, не смена семантики сохранения. Изменённые incoming по-прежнему помечаются «Не сохранено» / «Будет удалена»; доступно существующее действие сохранения. Для outgoing при грязной панели показана краткая причина «Сначала сохраните или отмените изменения задачи». В продукте не показывать слова draft, immediate, API, transaction. Постоянное дополнительное пояснение при чистом состоянии не нужно.

Все immediate пути, включая row, граф и Гант, проверяют guard и при открытии, и перед отправкой: busy/loading, pending/uncertain, conflict, dirty/raw-invalid panel, project edit и существующие journal locks. Запрещено обходить guard потому, что выбрана другая строка. Открытие цепочки не выбирает строку, не открывает карточку и не переносит QuickAdd. Если действие недоступно, есть доступная причина, а черновики сохраняются. Если guard меняется при открытом picker, запись становится недоступной. Закрытие picker не снимает locks. Граф incoming остаётся доступным для редактирования общего черновика, если обычные panel locks разрешают это.

## 4. Общий picker

### 4.1 Направление и контекст

В шапке видны название текущей задачи (для пустого QuickAdd — «Новая задача») и при необходимости путь родителей. Под ним подпись **«Эта задача выполняется»** и две компактные доступные кнопки **«После» / «Перед»** с обозначением выбранного состояния. При каждом новом открытии row/Gantt/QuickAdd default — «После»; смена направления действует только до закрытия слоя. Ни направление, ни поисковая строка не являются сохраняемыми данными.

| Режим | Выбранная задача A, текущая T | Предпросмотр |
|---|---|---|
| После | `A → T` | «A → T», доступный текст «T выполняется после A» |
| Перед | `T → A` | «T → A», доступный текст «T выполняется перед A» |

Предпросмотр виден до выбора для активного результата (при начальном Enter — первого результата), а выбранные chips сохраняют свою стрелку и подпись направления. Длинные/совпадающие названия различаются путями; текст доступен без обрезания смысла через accessible name/tooltip. Клик результата или Enter выполняет действие для показанного направления, без отдельного обязательного подтверждения. Нет автоматического открытия панели кандидата.

В QuickAdd две независимые группы IDs. Переключение «После → Перед» **не переносит, не разворачивает и не очищает** уже выбранные связи, включая несколько selections. Обе группы выбранного видны с подписями; кнопка удаления chip снимает только указанную связь. Число на QuickAdd chain — сумма обеих групп, с доступной подписью «Связи новой задачи: N, не сохранено». Для изменения направления уже выбранной связи пользователь явно удаляет её и добавляет заново. При повторном открытии default «После» не меняет ни одну группу.

В picker строки/Ганта существующей задачи обе группы сохранённых связей также видны и различимы. В fixed-direction picker графа показана только группа его секции. Удаление использует ID конкретного сохранённого ребра, независимо от текущей вкладки направления. Нельзя молча удалить обратное ребро, удалить задачу или отправить замену всех incoming вместо `dependency.delete`. Сохранённые рёбра остаются видимыми до подтверждения; duplicate candidate не предлагается повторно. Граф открывает тот же picker с фиксированным направлением без переключателя: выбранная секция уже определяет его; доступное имя содержит «Добавить предшественника» либо «Добавить последователя».

### 4.2 Кандидаты и валидация

Поиск идёт по полному текущему snapshot проекта, по названию и пути родителей, с trim и без учёта регистра, в полном порядке дерева. Фильтр списка, свёрнутая ветка или отсутствие реальных дат не скрывают кандидата. У бездатной работы остаётся понятная подпись неполного интервала; это не ошибка. Completed leaf не исключается только из-за статуса: допустимость записи и необходимого переноса проверяет сервер.

Кандидаты исключают self, summary, чужой проект, повтор уже выбранного ребра и ребро, создающее цикл. Для существующей задачи используются сохранённый граф либо panel incoming proposal, в зависимости от хозяина. Для новой — временный leaf с текущим `parentId`, все сохранённые рёбра и **обе** группы выбранных связей. Например, при существующем `B → A` выбор `A → T` делает `T → B` недопустимым. Проверка только выбранного направления недостаточна.

Новая подзадача превращает `parentId` в summary, поэтому родитель не кандидат даже если до создания был leaf. Изменение уровня ввода/обновление snapshot повторно проверяет выбранное. Исчезнувшая либо ставшая недопустимой связь остаётся в черновике с причиной и кнопкой удаления; её нельзя молча отбросить. До исправления известного invalid selection отправка недоступна. `preserveWork` остаётся существующим явно подтверждаемым преобразованием собственной работы родителя. Пользовательский ID в новом списке связей не переназначается неявно на созданную «собственную работу»; итоговые endpoints валидируются после преобразования сервером.

UI-фильтр помогает выбору, но не заменяет серверную проверку. Конкурентная смена revision, цикл, done-push, недоступный legacy source и overflow могут дать обычную командную ошибку. Полный DAG и итоговые leaf endpoints валидируются до каскада, включая взаимодействие входящих/исходящих новой задачи.

### 4.3 Состояния, клавиатура и фокус

При открытии фокус получает поиск. Сохраняются ArrowUp/ArrowDown, прокрутка активного результата в видимую область и Enter для активного/первого кандидата. Enter внутри picker не создаёт задачу внешней формы, не открывает строку и не запускает глобальные shortcuts; IME composition Enter не выбирает результат. Tab/Shift+Tab доступны для переключателя, поиска, chips, удаления и закрытия. Переключение направления сохраняет query, сбрасывает active result и пересчитывает кандидатов/предпросмотр; фокус остаётся на нажатом контроле.

Escape закрывает только picker и возвращает фокус на исходную цепочку/«+ Добавить», без закрытия карточки, отмены QuickAdd или потери выбранного. Крестик делает то же. Осознанный переход к другому контролу/задаче/проекту отзывает отложенное восстановление: поздний ack, retry или refresh не крадёт фокус, даже после последующего blur в body. Если исходный trigger исчез, локальный fallback — та же строка в исходном дереве, затем соответствующий QuickAdd; для графа — видимый заголовок секции/вкладка зависимостей. Скрытый/unmounted trigger не фокусируется. Закрытие при отправке может оставить одноразовый возврат после снятия disabled, только пока намерение фокуса не отозвано.

Popover остаётся в пределах viewport при росте chips/ошибки, resize, zoom и прокрутке; результаты прокручиваются внутри. Ничего не сдвигает высоту строки/Ганта. Состояния различимы: «Загрузка задач», отсутствие допустимых leaf, отсутствие совпадений query, ошибка загрузки с повтором, ошибка записи и ожидание. Нельзя показать пустой результат вместо loading/error. Во время pending недоступны выбор, удаление и смена направления; закрытие слоя не означает отмену запроса. Успешное состояние, counts и стрелки появляются только после валидного ack (локальный draft явно обозначен как несохранённый).

Обычный отказ сохраняет контекст, query и draft, позволяет исправить данные и повторить новое действие. При 409 черновики сохраняются, предлагается существующее обновление snapshot и повторная валидация; автоматического повторного применения к новой revision нет. При неизвестном результате сохраняется точный envelope (operationId, revision, command, оба массива IDs); разрешён только existing exact retry. Закрытие/повторное открытие picker не создаёт новый operationId и не меняет pending payload. После frozen ack ниже уже известной revision применяется существующий refresh/revision-floor flow, а не откат UI к старому snapshot. Logout/401 очищают private RAM по прежним правилам.

## 5. Строки дерева и счётчики

Цепочка добавляется после существующих иконок «Добавить подзадачу» и «Добавить запись»; последние сохраняют своё поведение. Доступное имя — «Зависимости: <название>», подпись включает число сохранённых входящих и исходящих. Leaf chain видна у выбранной строки, при hover или focus-within строки, а при наличии сохранённых связей — постоянно вместе со счётчиком; в `hover: none` доступна без необходимости сначала открывать панель. Click/Enter/Space кнопки не всплывают в выбор строки, создание подзадачи или drag. Скрытая кнопка не перехватывает pointer, а клавиатурный фокус делает её видимой. Summary показывает недоступное действие с пояснением «Связи только между конечными задачами»; draft preview строки не получает этот вход.

N — число непосредственных сохранённых incident edges leaf (`incoming + outgoing`), не число потомков/транзитивных путей и не результат фильтра. При N > 0 сама кнопка цепочки со счётчиком видна постоянно, в том числе без hover/selection и при закрытой панели, и сразу открывает picker. Ноль не рисуется. Цепочка и число — одна кнопка с одним tab stop, без отдельного дублирующего индикатора/действия. Кнопка не скрывается вместе с датой при показе row actions. Черновик incoming панели и незавершённый запрос не меняют сохранённый N; у панели/QuickAdd есть собственная маркировка несохранённого.

Рабочая геометрия C30/D25 сохраняется: 38 px строки, click targets не меньше 28×28, дата и header выровнены, правые действия внутри видимой колонки, включая 300 px Гант и глубокую вложенность. Дополнительные действия показываются над концом строки с фоном строки и скрывают только перекрываемую дату; при их появлении название/цепочка со счётчиком не прыгают. Постоянная цепочка с числом при N > 0 имеет собственное место и не закрывает дату в обычном состоянии. Это тот же DOM control при hover/focus, а не заменяющая копия. Точное размещение и резерв места план уточняет по существующей row CSS с сохранением доступного полного title; нельзя добавлять фиксированную широкую колонку зависимостей или раздвигать дерево/Гант. Проверить сочетание count, длинного названия, diagnostics/critical marker и узкой колонки на фактическом UI.

## 6. Симметричный граф панели

В едином визуальном контейнере последовательно: секция «Предшественники (N)» → текущая задача → секция «Последователи (M)». Обе секции имеют одинаковые padding, начало текста, заголовок/счётчик и «+ Добавить» на одном относительном месте справа в строке заголовка. Accessible names кнопок содержат направление. Пустая секция показывает однотипное короткое сообщение и сохраняет доступную кнопку. Summary сохраняет объяснение leaf-only и существующие переходы к конечным работам.

Стрелки направлены от каждого предшественника в текущую задачу и от неё в каждого последователя. Навигация по карточкам, статусы, реальные даты/«Без дат», critical/partial labels, «Показать на Ганте» и подробности расчёта сохраняются. Внешний заголовок predecessor переносится внутрь; действия/«Показать ещё» не должны создавать визуально разные секции. По четыре карточки на секцию и отдельная пагинация сохраняются как рабочий default; счётчик показывает всю секцию, не текущую страницу. При удалении последней карточки страницы offset корректируется, текущая задача остаётся между секциями.

Входящие N показывает размер итогового incoming draft; помеченные «Будет удалена» карточки могут ещё оставаться видимыми для восстановления, но не входят в N. Несохранённое изменение секции отмечено рядом со счётчиком, сохранённое число вкладки панели по D22 остаётся отдельным baseline. Исходящие M всегда берётся из ack snapshot. Счётчики не изображают ожидающую запись как сохранённую. В графе нет переключателя «После / Перед»; fixed-direction picker имеет ту же строку поиска, preview и состояния.

## 7. Атомарное создание с последователями

[ADR 015](../../adr/015-create-successor-dependencies.md) задаёт единственное расширение контракта: optional `task.create.successorIds: string[]`. `predecessorIds` и `successorIds` независимы; absent и `[]` означают отсутствие рёбер соответствующей стороны для новой задачи. Только UUID, уникальные внутри каждого массива. Пересечение массивов создаёт двусторонний цикл и отклоняется целиком. Contract version 2, Task/ProjectTree DTO, SQL, `task.edit`, исторические payload/response остаются прежними. Старые команды без поля принимаются; сериализация старого payload не должна получать новое default поле, иначе сломается exact replay.

Сервер сначала готовит создание/порядок/parent conversion в candidate snapshot, затем все `P → T` и `T → S`, валидирует окончательный DAG и выполняет один существующий causal cascade по всем added edge IDs. Только затем calculate/сохранение revision/outcome/undo. Не выполнять последовательность HTTP create и add; даже ошибка последнего outgoing откатывает задачу, оба набора рёбер, преобразование родителя, даты, порядок, revision и undo. У неизменённых существующих рёбер сохраняются IDs. Новый outbound не заменяет остальные incoming выбранного successor.

Пример: календарь weekdays, A заканчивается 2026-11-09, T задана 2026-11-09…2026-11-10 (duration 2), B задана 2026-11-10…2026-11-11 (duration 2). Одна create с `A → T → B` переносит T на 10…11 ноября, B на 12…13 ноября; один Undo возвращает B на 10…11, удаляет T и оба ребра. Если у T обе даты null, выбор «Перед B» не выводит её даты из B; исходные nullable поля сохраняются, conditional display остаётся только представлением. Если B done и требуется push, вся команда отклоняется.

В `QuickDraft`, `hasQuickDraft`, comparison/captured submission, resets, main/subtask scope и rebase добавляется второй набор IDs. Successor-only считается непустым черновиком и не переносится при обычном выборе строки по C31. Успешный ack очищает только соответствующий полный совпадающий draft и raw generation, не новый ввод/другую ветку; оба набора очищаются вместе. После обычной ошибки/409/потери ответа обе стороны сохраняются. Retry не генерирует повторную задачу/рёбра, не выполняет cascade второй раз; Undo creation восстанавливает полный before-snapshot с прежними journal collision checks.
