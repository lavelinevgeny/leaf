# C19 — условные полосы и создание задач

Принято владельцем 2026-10-08. Дополнение C14/C18, замена ограничений D13. Реальные даты, необязательность полей, календарь проекта, C12/C16/C17 и атомарные записи сохраняют прежний контракт.

## Отображение конечной работы

| Исходные поля | Полоса |
|---|---|
| Валидная сохранённая пара дат | Реальный интервал независимо от наличия duration |
| Только начало | Условно от начала на duration или один display-день |
| Только окончание | Условно до окончания на duration или один display-день |
| Нет обеих дат, есть известные начала в родительской группе | Условно от минимума начал этой группы |
| Нет обеих дат и групповой опоры | Условно от сегодня в timezone проекта |

Длина бездатных полос — duration или один display-день. Корневая задача не использует общий минимум проекта. Групповой минимум учитывает полные данные вложенных ветвей, включая одиночное начало; фильтры/сворачивание его не меняют. Собственная дата приоритетнее группы. Родитель с детьми остаётся summary: обе сводные границы известны только при всех реальных интервалах; условный today для summary запрещён.

Неполные полосы приглушены и имеют tooltip/доступную подпись «Условное размещение; полный интервал не задан». Исходные даты отдельно читаемы, колонка бездатной задачи остаётся «Без дат». Условные края не участвуют в summary, FS, coverage и CPM. Уточнение отображения C24 от 2026-10-08: сохранённая FS-связь видна между условными полосами пунктирной стрелкой с подписью «Связь; условное размещение, полный интервал не задан». Края используются только для её геометрии, не как реальные даты или подтверждение соблюдения FS. Это заменяет прежнее скрытие стрелок при отсутствии реальных дат. Enter/Space открывает панель; клавиши стрелок, drag и resize не записывают условный план.

Окончание включительно. Первый день занимает сам anchor, следующие идут по календарю проекта. Weekdays: начало пятница 09.10.2026 + 2 дня → окончание понедельник 12.10.2026; окончание понедельник 12.10.2026 − 2 дня → начало пятница 09.10.2026. Одиночная суббота с duration=1 занимает субботу; duration=2 от субботы заканчивается в понедельник, до субботы начинается в пятницу. Это только display. При переполнении диапазона 0001–9999 рисунок ограничивается крайним поддерживаемым днём с пояснением; source duration не меняется. Лимит нового ввода 1–1 000 000 не отбрасывает большую сохранённую положительную duration: для неё также используется ограниченное отображение. Невалидные исходные поля или недоступная полная пара не превращаются в условный план.

## Граница сервер / представление

Один чистый domain helper принимает nullable исходные поля, известную групповую опору, nullable today и календарь. Он не читает часы и не изменяет вход. Сервер передаёт today=null и рассчитывает own/group display при прежнем пересчёте. Представление передаёт текущую календарную дату для fallback. Response DTO, SQL, migration, frozen replies и authoritative CPM не меняются. task.create получает три необязательных source поля из существующей sourcePatchSchema, с nullable defaults и серверной проверкой полного интервала; версия контракта остаётся 2.

Сегодня вычисляется в timezone проекта, обновляется при возвращении вкладки в фокус и не реже одного раза в минуту. Смена дня передвигает только today-полосы и линию сегодня, без revision, mutation и undo. «Показать на Ганте» находит условные own/group/today полосы.

## Создание и явный выбор даты

Быстрый ввод дерева и подзадач имеет раскрываемый блок «Сроки новой задачи» на общих полях C18. Новый черновик: durationDays=1, inputStart/inputFinish=null. Длительность можно изменить/очистить; очистка остаётся null. API без явно переданных полей сохраняет прежний default null. Существующие задачи при открытии не получают duration=1.

Кнопка «Сегодня» рядом с началом задаёт фактическое сегодня в timezone проекта по явному действию и запускает C18 в черновике. При duration=1 на рабочем дне обе даты совпадают. В календаре weekdays выходной не нормализуется молча: действует существующая ошибка C18, пользователь выбирает допустимую дату или очищает длительность. Открытие/фокус формы не задаёт дату. Кнопка применяется и к редактированию существующей работы; done/summary/locked сохраняют ограничения.

Сроки и название сохраняются одной task.create. Ошибка завершённого ввода не снимается сворачиванием/повторным раскрытием блока; исправление поля или явный сброс возвращает возможность создания. Черновики названия, сроков и контекста отдельны для проекта и панели ветви; failed/uncertain запрос не очищает их, exact retry сохраняет тот же payload и сбрасывает только соответствующий черновик. Успех/явный сброс возвращает duration=1 и пустые даты. Logout/beforeunload учитывают изменённые сроки даже без названия. Undo создания удаляет задачу одной операцией.

## Проверяемые примеры

- Date-less root, today=08.10.2026: duration=null → 08.10; duration=3 → 08–12.10 в weekdays.
- Finish-only=12.10.2026, duration=2, group=05.10: условно 09–12.10; source start=null, coverage и summary прежние.
- Start-only=09.10.2026, duration=null: условно 09.10, source finish/duration=null.
- Group=05.10 при today=08.10: бездатный ребёнок от 05.10, бездатный root от 08.10. Смена today на 09.10 меняет только root.
- Real pair=05–06.10 без duration: обычная полоса; incomplete summary и invalid/unavailable pair без полосы.
- Пустой проект, новый ввод: duration=1 видна после раскрытия, даты пусты; очистка и создание сохраняют null. Today с duration=1 сохраняет рабочую пару только после submit.
- Browser: изменение дня/timezone, reveal, фильтр, Enter/Space, отсутствие writes/FS/critical для условных краёв, реальный create/retry/undo/restart на синтетическом runtime.

## Границы

Без новых зависимостей, схем хранения, миграций, автопланирования, resources, holiday calendar или изменений S4 доски/S5/S6. Три утверждённых PNG остаются ориентирами; новый subtask layout не создаётся.
