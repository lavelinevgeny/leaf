# ADR 003 — локальное восстановление пароля

Дата: 2026-10-07. Статус: реализованное инженерное решение для восстановления локального входа.

## Контекст

Первичная настройка отказывает при существующем аккаунте. Ошибка при скрытом вводе или утраченный пароль требуют смены пароля без потери дерева задач. Собственный посимвольный ввод ошибочно включал части управляющих последовательностей стрелок и вставки в пароль.

## Решение

Команда `admin:reset-password` доступна только владельцу локального интерактивного терминала с доступом к SQLite. Она использует тот же `LEAF_DATA_DIR`, что приложение, требует двукратного скрытого ввода и сохраняет действующие параметры scrypt. Пароль не передаётся через args/env. HTTP endpoint и удалённый setup не добавляются; существующие origin checks, cookies и rate limits сохраняются.

Изменение хеша, отзыв всех сеансов и удаление привязанной к сеансам истории отмены выполняются одной SQLite-транзакцией. Проекты, задачи и ревизии сохраняются. Вход повторно сверяет хеш внутри транзакции выдачи сеанса: проверка старого пароля, начатая до reset, не может выдать новый сеанс после смены хеша.

Скрытый ввод использует Node readline с отключённой историей и заглушённым выводом. Это обеспечивает обработку Unicode, Backspace, стрелок и bracketed paste без попадания управляющих последовательностей в пароль. Отмена и завершение восстанавливают режим терминала.

## Последствия и проверки

Доступ к локальному runtime уже позволяет изменить SQLite; команда не расширяет удалённую поверхность приложения. Владелец запускает восстановление самостоятельно. При выборе другого каталога команда не меняет учётную запись исходной базы.

Тесты проверяют отсутствие echo, редактирование ввода, сохранность задач, отказ старого пароля и cookies, отсутствие удалённого endpoint, rollback и гонку входа со сменой хеша. Пользовательские базы и пароли не используются для проверки.
