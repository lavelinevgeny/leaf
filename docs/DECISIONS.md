# Решения и допущения

Этот реестр сохраняет смысл обсуждения, но не публикует полную переписку. Обозначения: **C** — прямо подтверждено пользователем; **D** — предлагаемое рабочее решение; **O** — открытый вопрос. D можно использовать, чтобы начать разработку, но нельзя выдавать за отдельное согласование.

| C16 | Принята политика критического пути по введённым валидным парам дат без назначения/переноса source dates: единый горизонт, обратный проход, раздельные projectFloat/constraintFloat, tight FS и отдельный анализ датированной части при unknown. Формулы и P01–P11 — в [нормативном приложении](superpowers/specs/2026-10-07-optional-scheduling-policy-proposal.md), [ADR 008](adr/008-explicit-date-cpm.md). |
| C17 | Принята однократная конвертация доступных абсолютных legacy Auto/done интервалов в явные даты с точным private archive; для done приоритет у сохранённого completed интервала. Правила и M01–M10 — в [нормативном приложении](superpowers/specs/2026-10-07-optional-scheduling-policy-proposal.md), [ADR 007](adr/007-legacy-scheduling-migration.md). |
| C18 | 2026-10-08: в панели начало, окончание и длительность связаны при явном завершении ввода. Начало сохраняет длительность и пересчитывает окончание; окончание сохраняет начало и пересчитывает длительность; длительность сохраняет начало и пересчитывает окончание, а без начала использует окончание для расчёта начала. При двух датах без длительности редактирование даты рассчитывает длительность. Поля необязательны: очистка меняет только очищаемое поле, одна длительность не назначает даты. Пересчёт после blur/Enter/выбора даты, компактная длительность с единицами рядом, даты DD.MM.YYYY и краткая подсветка пересчитанного значения. Это явная подготовка атомарного patch, не фоновое назначение сроков. Правила — [§3.3 спецификации](superpowers/specs/2026-10-07-optional-scheduling-design.md). |

| C19 | 2026-10-08: утверждены условные полосы всех конечных задач с неполным интервалом. Приоритет: собственное начало, собственное окончание (обратный отсчёт), минимум известных начал в родительской группе, сегодня в timezone проекта. Длина — заданная длительность или один display-день; обе реальные даты всегда имеют приоритет. Условные значения не сохраняются и не участвуют в summary/FS/coverage/CPM; завтра today-полоса обновляется без записи. В форме создания длительность предзаполнена 1 и очищаема, даты пусты; кнопка «Сегодня» явно задаёт начало по C18. task.create принимает необязательные source поля; API без указанных полей сохраняет nullable defaults. [Спецификация C19](superpowers/specs/2026-10-08-conditional-gantt-design.md) уточняет C14 и заменяет ограничения D13. |

Кнопка `?` и локальная справка Ганта удалены; общая справка пока не реализована. Уточнение 2026-10-09: `⋯` появляется при наведении или клавиатурном фокусе в любой строке проекта, включая невыбранные. Без нового раздела анализа, новых действий проекта, библиотек или изменения scheduler/API. [Спецификация C20](superpowers/specs/2026-10-08-compact-workspace-design.md). |

| C21 | 2026-10-08: быстрый ввод подзадачи в строке через «+ Подзадача» при наведении или Shift+Enter. Tab/Shift+Tab меняют уровень в поле названия, Alt+D открывает сроки. Один чип показывает даты/длительность; пресеты «Сегодня», «Завтра», «До пятницы», «Как у родителя» при известных сроках. Начало, окончание и редактируемая длительность связаны по C18. Черновик до сохранения и конечные задачи с неполным интервалом показываются приглушённым пунктиром по C19; условные даты не сохраняются и не входят в CPM. Undo в шапке — иконка с доступным именем и tooltip; это уточнение заменяет подпись из C20. Отдельный deadline по C15 остаётся исключённым. |

| C22 | 2026-10-08: согласованы две кнопки «Список / Гант», удаление постоянной даты периода, одинаковая высота управления и заголовков в обоих видах, сохранение прокрутки/выбора/веток/черновиков. Поиск видим; статус — в popover «Фильтры», счётчик совпадений внутри существующей строки, нулевой результат в области задач. [Спецификация C22](superpowers/specs/2026-10-08-stable-view-controls-design.md) уточняет C20; API/scheduler не меняются. |

| C23 | 2026-10-08: уточнено оформление шапки с отменой, поиском и зелёной кнопкой «Фильтры»; переключатель «Список / Гант» получает иконки и мягкое выделение активного вида. Статусы выбираются несколькими чекбоксами со счётчиками задач; выбор применяется кнопкой «Применить», выбранное количество видно на кнопке фильтров. | C25 | 2026-10-08: при установке FS-связи начало зависимой работы должно быть строго после включительного окончания предшественника; ранние даты переносятся, в том числе при одновременном изменении сроков и добавлении связи в карточке. Работы без обеих дат отображаются с учётом зависимости без назначения реальных дат. [Спецификация C25](superpowers/specs/2026-10-08-fs-link-placement-design.md); подробности отображения — рабочий D18. |
| C26 | 2026-10-08: критичность датированной части выделяется только цветом, без пунктирной или утолщённой границы. Подписи критичности сохраняются. | C24 | 2026-10-08: связь «начать после окончания другой работы» независима от родства. Ввод доступен при создании, в карточке и на Ганте; уточнение 2026-10-09 убирает цепочку из строк списка, включая левую часть режима Ганта и дерево подзадач, сохраняя «+ Подзадача»; перенос предшественника переносит зависимую работу и пересчитывает критичность родительской ветки. UX остаётся простым. Сохранённая связь должна быть видна на Ганте и при неполных датах; условная геометрия не становится реальными сроками. | C27 | 2026-10-09: левая ручка реальной полосы Ганта меняет начало при фиксированном включительном окончании и пересчитывает длительность по календарю. [Спецификация](superpowers/specs/2026-10-09-gantt-start-resize-design.md) и [план](superpowers/plans/2026-10-09-gantt-start-resize.md); реализация выполнена отдельными агентами с независимыми review; результаты — в [STATUS](STATUS.md). |

| C28 | 2026-10-09: подготовить бесплатное демо leaf на Render с будущим постоянным URL; потеря демонстрационных данных допустима, каждый запуск должен автоматически создавать синтетический пример. Владелец поручил обновить спецификации, подготовить и исполнить план отдельными агентами, с независимым review каждого блока и коммитом только после положительного review. Реальная публикация/deployment отдельно не разрешены. [Спецификация](superpowers/specs/2026-10-09-render-demo-design.md), [план](superpowers/plans/2026-10-09-render-demo.md). |

## Рабочие решения по умолчанию

| ID | Default и причина |
|---|---|
| D01 | Один пользователь, несколько независимых проектов, один локальный вход. Нет команд и прав доступа. |
| D02 | Основной клиент — desktop web, русский UI. Английские идентификаторы; строки собраны централизованно без полной системы переводов. |
| D03 | Один TypeScript-пакет, React/Vite + Fastify + SQLite. Подробности в ARCHITECTURE. |
| D04 | Даты с точностью до дня; календарь проекта «все дни» или «пн–пт»; default — пн–пт. |
| D05 | Зависимости только Finish-to-Start, без лагов, между конечными работами одного проекта. |
| D06 | Родитель с детьми — сводная задача. Не отдельная дополнительная длительность. |
| D07 | Сценарий Auto с началом проекта и вводом длительности отменён решением C11; отдельный контрольный дедлайн исключён решением C15. Явные даты — исходные данные. Auto и deadline относятся к историческому контракту S2–S3; Tasks 5–7 адаптировали текущие source/storage/API/UI и CPM. Проверки и ограничения — в [STATUS](STATUS.md). |
| D08 | Три статуса: todo / doing / done. Готовность не обнуляет длительность. |
| D09 | Доска остаётся запланированным представлением V1 из обсуждённых границ. Она вторична относительно дерева и Ганта, дизайн доски не выбран. |
| D10 | Список и Гант — один экран с включаемой шкалой; выбранная компактная панель поверх правой части. |
| D11 | Отмена в текущей сессии с проверкой ревизии проекта; перезапуск приложения не обязан сохранять стек undo. |
| D12 | Прогноз по текущему плану, не полноценный actual/remaining forecast. Нет ресурсного выравнивания. |
| D13 | Отображение C14: точка привязки — минимум известных начал подзадач того же родителя; C19 заменяет прежний запрет полос без точки привязки и добавляет приоритет собственной даты; без опоры используется сегодня. Если обе даты заданы, полоса показывает их интервал. Приглушённое размещение и fallback одного дня не записываются в исходные поля и не используются как реальные сроки в сводных датах/CPM. Это рабочее уточнение границ отображения, а не отдельно подтверждённая семантика расчёта. |
| D14 | S4, 2026-10-08: поиск по названию — буквальная подстрока без учёта регистра, с trim и Unicode NFC; прежний фильтр по одному статусу todo/doing/done заменён множественным выбором C23, по умолчанию все. Условия объединяются через AND. Показываются совпадения и все их родители; совпавший родитель не включает автоматически остальных детей. Раскрытие результатов отдельно от обычного дерева, сброс возвращает прежнее сворачивание. Фильтры сбрасываются при смене проекта; «Показать на Ганте» снимает их для выбранной задачи. Рабочее решение первой задачи [S4](superpowers/plans/2026-10-08-s4-task-filters.md), не новое подтверждённое C. |
| D15 | S4, 2026-10-08: вкладка «Подзадачи» показывает полную ветку на общем дереве независимо от основного поиска. Ввод ограничен выбранной веткой; черновики отдельны для основного экрана и каждой панели, живут в текущей клиентской сессии. Переход к ребёнку сохраняет возврат к родителю, вкладке и строке; при исчезновении строки фокус возвращается к вводу. Рабочее уточнение второй задачи S4 по [UI](UI.md), не утверждение отдельного subtask layout. |

| D16 | Уточнение C23: статусы объединяются через OR, с поиском через AND. «Все статусы» выбирает весь набор; частичный набор даёт mixed-состояние общего чекбокса, пустой — ноль совпадений. Счётчики рядом со статусами относятся ко всем задачам текущего проекта, независимо от поиска и сворачивания; родители контекста не увеличивают счётчик найденных. Бейдж показывает число выбранных статусов при ограничении набора (включая 0), при полном наборе скрыт с сохранением ширины. Escape, внешний клик, уход Tab, loading и смена проекта отменяют неприменённый выбор; новое открытие берёт применённое состояние. «Применить» возвращает фокус на кнопку фильтров, «Сбросить» сразу очищает поиск/статусы и возвращает фокус в поиск. |

| D18 | Рабочее уточнение C25: только у конечной работы с обеими датами null условное начало равно максимуму опоры C19 и следующего рабочего дня после доступных real/conditional окончаний входящих predecessors. Полный DAG до filters/collapse; условная цепочка не влияет на source/CPM/summary. Одинарные исходные даты сохраняют C19. При display overflow — clipped, без ошибки записи. [Правила и примеры](superpowers/specs/2026-10-08-fs-link-placement-design.md). |
| D17 | Рабочие правила C24: leaf-only FS одного проекта, лаг 0. Причинный каскад при записи переносит только необходимую позднюю границу; ранний перенос возможен для tight-цепочки с достоверными входящими границами. Промежуток поглощает задержку, сохранённых anchors нет; удаление связи не подтягивает даты. Пустые source даты не материализуются; nullable duration сохраняется. Done не переносится; C25 разрешает нормализацию source edit при добавленном входящем ребре. Необходимый push завершённой работы, прочий прямой source-конфликт и непереносимый затронутый интервал отклоняют всю команду. Create/Details сохраняют task/source/predecessors одним draft-command; список/Гант — existing immediate edge command, только после ack. Правила причинных барьеров, unavailable provenance, exact retry/undo — в [§§2–5 спецификации](superpowers/specs/2026-10-08-fs-dependencies-design.md). C16 остаётся чистым анализом; C24 расширяет команды записи перед ним. |

| D19 | Рабочее техническое уточнение C27, 2026-10-09: additive V2 task.resizeStart вычисляет duration на сервере и сохраняет finish; старые task.edit/правый resize/C18 не меняются. Реальное изменение начала записывает inclusive span даже при прежнем null duration; no-op сохраняет null. Pointer target на выходном отклоняется без snapping; keyboard шагает по рабочим дням. Incoming FS конфликт отклоняется атомарно без переноса окончания; неизменный finish не переносит downstream. [Полные правила и приёмка](superpowers/specs/2026-10-09-gantt-start-resize-design.md). |

| D20 | Рабочие технические правила C28: только LEAF_DEMO_MODE=1, shared editable workspace, явная кнопка «Открыть демо» без пароля через обычную opaque session, optional demoMode в session API и conditional POST /api/auth/demo. ## Не считать утверждённой функциональностью

На выбранных рисунках есть аватары, исполнитель, приоритет, метки, вложения, комментарии, отдельные вкладки «Календарь», «Файлы», «Заметки». Предыдущие сообщения ассистента перечисляли их, но явного запроса реализовать каждую функцию не было. Они также противоречат ранее предложенной границе «без команд, меток и вложений».

**Рабочее разрешение противоречия:** сохранить выбранную компоновку, но в первом релизе показывать только работающие необходимые элементы: детали, подзадачи, зависимости и настройки проекта. Дополнительные функции — backlog, без неработающих вкладок. Перед их включением нужно отдельное подтверждение, а не ссылка на пиксели макета.
