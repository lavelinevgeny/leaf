# Решения и допущения

Этот реестр сохраняет смысл обсуждения, но не публикует полную переписку. Обозначения: **C** — прямо подтверждено пользователем; **D** — предлагаемое рабочее решение; **O** — открытый вопрос. D можно использовать, чтобы начать разработку, но нельзя выдавать за отдельное согласование.

|---|---|
| C01 | Программа называется `leaf`. |

| C04 | У задачи могут отсутствовать начало, окончание или обе даты. |

| C07 | Выбрана компактная правая панель задачи, вариант 1. |

| C10 | Репозиторий публичный, подготовлен для Codex и Claude; нельзя выгружать секреты и личные данные. |
| C11 | Общий сценарий автоматического назначения сроков от даты начала проекта не нужен. Длительность задачи допускается как необязательное поле по C13, без возврата этого сценария. Подтверждено и уточнено 2026-10-07; заменяет соответствующую часть D07. |
| C12 | Сводные сроки родителя — минимальное начало и максимальное окончание подчинённых задач. Если полный сводный интервал определить нельзя, он не показывается; частичный диапазон не выдаётся за сводные сроки. Подтверждено 2026-10-07; заменяет прежний partial-summary default. |
| C13 | У задачи могут быть начало, окончание и длительность; каждое поле необязательно. Подтверждено 2026-10-07. |
| C14 | Если у родителя есть подзадачи с датами, подзадачи без начала отображаются на Ганте приглушённой полосой от минимальной известной даты с учётом длительности. Если длительность не задана, для такого отображения используется один день. Подтверждено 2026-10-07; исключение из прежнего запрета полос для задач без дат. |
| C15 | Отдельный дедлайн не нужен. В целевой модели и интерфейсе остаётся необязательная дата окончания без отдельного контрольного срока. Подтверждено 2026-10-07; отменяет соответствующее допущение D07. |
| C16 | Принята политика критического пути по введённым валидным парам дат без назначения/переноса source dates: единый горизонт, обратный проход, раздельные projectFloat/constraintFloat, tight FS и отдельный анализ датированной части при unknown. Duration-only и условные полосы не участвуют. Подтверждено 2026-10-07; закрывает O06/G-CPM как выбор политики. Формулы и P01–P11 — в [нормативном приложении](superpowers/specs/2026-10-07-optional-scheduling-policy-proposal.md), [ADR 008](adr/008-explicit-date-cpm.md). |
| C17 | Принята однократная конвертация доступных абсолютных legacy Auto/done интервалов в явные даты с точным private archive; для done приоритет у сохранённого completed интервала. Relative indices переводятся только с опорой того же historical state; при её отсутствии source/status сохраняются с unknown и диагностикой. Подтверждено 2026-10-07; закрывает выбор G-MIGRATION. Нужны aggregate preview и подтверждение конкретного upgrade; это не разрешение production operation. Правила и M01–M10 — в [нормативном приложении](superpowers/specs/2026-10-07-optional-scheduling-policy-proposal.md), [ADR 007](adr/007-legacy-scheduling-migration.md). |
| C18 | 2026-10-08: в панели начало, окончание и длительность связаны при явном завершении ввода. Начало сохраняет длительность и пересчитывает окончание; окончание сохраняет начало и пересчитывает длительность; длительность сохраняет начало и пересчитывает окончание, а без начала использует окончание для расчёта начала. При двух датах без длительности редактирование даты рассчитывает длительность. Поля необязательны: очистка меняет только очищаемое поле, одна длительность не назначает даты. Пересчёт после blur/Enter/выбора даты, компактная длительность с единицами рядом, даты DD.MM.YYYY и краткая подсветка пересчитанного значения. Это явная подготовка атомарного patch, не фоновое назначение сроков. Правила — [§3.3 спецификации](superpowers/specs/2026-10-07-optional-scheduling-design.md). |

| C19 | 2026-10-08: утверждены условные полосы всех конечных задач с неполным интервалом. Приоритет: собственное начало, собственное окончание (обратный отсчёт), минимум известных начал в родительской группе, сегодня в timezone проекта. Длина — заданная длительность или один display-день; обе реальные даты всегда имеют приоритет. Условные значения не сохраняются и не участвуют в summary/FS/coverage/CPM; завтра today-полоса обновляется без записи. В форме создания длительность предзаполнена 1 и очищаема, даты пусты; кнопка «Сегодня» явно задаёт начало по C18. task.create принимает необязательные source поля; API без указанных полей сохраняет nullable defaults. [Спецификация C19](superpowers/specs/2026-10-08-conditional-gantt-design.md) уточняет C14 и заменяет ограничения D13. |

| C20 | 2026-10-08: утверждено компактное рабочее пространство: название/меню проекта, поиск/статус, сразу дерево с включаемым Гантом. Постоянная сводка coverage/неполных сроков/CPM убирается; отсутствие дат нормально. Календарь/timezone и переименование доступны по запросу; реальные ошибки возле затронутых строк и подробно в панели; partial/global labels различимы. Уточнение владельца: меню `⋯` рядом с выбранным проектом слева, отмена с подписью в шапке перед поиском; повтор «Задачи» удалён, переключатель Ганта объединён с управлением шкалой. Кнопка `?` и локальная справка Ганта удалены; общая справка пока не реализована. Без нового раздела анализа, новых действий проекта, библиотек или изменения scheduler/API. [Спецификация C20](superpowers/specs/2026-10-08-compact-workspace-design.md). |

| C21 | 2026-10-08: быстрый ввод подзадачи в строке через «+ Подзадача» при наведении или Shift+Enter. Tab/Shift+Tab меняют уровень в поле названия, Alt+D открывает сроки. Один чип показывает даты/длительность; пресеты «Сегодня», «Завтра», «До пятницы», «Как у родителя» при известных сроках. Начало, окончание и редактируемая длительность связаны по C18. Undo в шапке — иконка с доступным именем и tooltip; это уточнение заменяет подпись из C20. Отдельный deadline по C15 остаётся исключённым. |

## Не считать утверждённой функциональностью

На выбранных рисунках есть аватары, исполнитель, приоритет, метки, вложения, комментарии, отдельные вкладки «Календарь», «Файлы», «Заметки». Предыдущие сообщения ассистента перечисляли их, но явного запроса реализовать каждую функцию не было. Они также противоречат ранее предложенной границе «без команд, меток и вложений».

**Рабочее разрешение противоречия:** сохранить выбранную компоновку, но в первом релизе показывать только работающие необходимые элементы: детали, подзадачи, зависимости и настройки проекта. Дополнительные функции — backlog, без неработающих вкладок. Перед их включением нужно отдельное подтверждение, а не ссылка на пиксели макета.

|---|---|---|

| O05 | Домен и окружение production? | Только локальные примерные адреса; не выполнять deployment. |
