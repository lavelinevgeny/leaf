# leaf — START HERE

**Главный файл для агента разработки.** Прочитай этот документ и `AGENTS.md`, затем выполняй текущую задачу владельца. Начинай S0 только по запросу на реализацию приложения. Не возвращайся к поиску готовых таск-менеджеров и не начинай новый раунд выбора интерфейса.

leaf — лёгкий self-hosted планировщик: **дерево задач + необязательные даты + Гант + автоматически пересчитываемый критический путь**. Простой интерфейс не означает упрощённые или фиктивные расчёты.

## 4. Рекомендуемая реализация

**Один TypeScript-проект, один package.json и один production-контейнер.** React + Vite в браузере; Fastify на сервере; SQLite; чистый модуль расчёта без зависимости от UI. Обычный npm с lockfile. CSS Modules и CSS-переменные; никаких обязательных внешних облаков, CDN, аналитики и AI API в самом приложении.

Это рабочая рекомендация, а не пользовательский выбор конкретного фреймворка. Менять стек можно только с коротким обоснованием в ADR, без увеличения сложности. Не вводи микросервисы, Redis, брокеры, Kubernetes, SSR или тяжёлый monorepo-tooling.

## 5. Этапы реализации

S0–S3 реализованы по прежним defaults: дерево/SQLite, чистый планировщик и атомарные API-команды, настоящий Гант, выбранная схема зависимостей и управление планом в панели. Адаптация storage/API/UI к C11–C17 выполнена в Task 5; Task 7 реализовал CPM по принятой C16 и прошёл финальные review/root gates 2026-10-08. В S4 реализованы поиск/фильтр по статусу с родительским контекстом и вкладка «Подзадачи» на общем дереве/быстром вводе. Синтетический прототип иерархической доски подготовлен; следующая задача — проверка компоновки владельцем (O03), затем подключение статусов и undo. Первый релиз требует завершения S4–S6; завершённые вехи не заменяют релизную приёмку.

Перед изменениями посмотри `git status`, определи существующий код и составь короткий план. Не останавливай разработку ради второстепенных неизвестных: используй явно обозначенные defaults. Спрашивай только о блокирующих, необратимых или расширяющих объём решениях.

## 6. Команды, которые уже существуют

```sh
npm run check:kit
npm run security:workspace
```

Они не требуют `npm install`: служебные скрипты используют стандартную библиотеку Node. Полный `test:kit` теперь требует установленный Gitleaks и проверяет его настоящим движком; отсутствующий scanner не превращается в skipped test. В `.nvmrc` зафиксирован Node 24.21.0; точные зависимости приложения и npm 11.19.0 закреплены вместе с lockfile. Для приложения: `npm run verify`, `npm run format:check`, `npm run test:e2e`, `npm run check:package`; browser install описан в BOOTSTRAP.

После помещения в Git-корень, проверки конфигурации и установки Gitleaks:

```sh
npm run hooks:install
npm run doctor
npm run preflight
```

`doctor` проверяет конфигурацию и инструменты. `preflight` проверяет комплект, тесты, public workspace, index guard, staged secrets через Gitleaks, историю и Git metadata; он не меняет index. Перед первым preflight подготовить проверенную `.gitleaks.toml` в index по BOOTSTRAP. Проверка настоящего Codex sandbox: `npm run agent:sandbox`. Профили и ограничения описаны в AGENT_WORKFLOW.

Установка хуков — явное действие, не скрытый postinstall. Не отключай их при ошибках. Публикация / push / выпуск образа требуют отдельного разрешения владельца. Доступ к репозиторию не равен разрешению публиковать его содержимое.

## 7. Публичный репозиторий

В репозитории разрешены только исходники, синтетические фикстуры, документация и проверенные макеты. Реальные задачи, базы, выгрузки, ключи, `.env`, логи, трассировки браузера, истории агентов и персональные настройки туда не попадают. `AGENTS.md` — инструкция, не техническая изоляция. Работай без доступа к production-данным.

Прочитай [docs/PRIVACY.md](docs/PRIVACY.md) **до первого коммита**. Хуки и CI не гарантируют отсутствие любых персональных данных и не заменяют ручную проверку. CI запускается уже после отправки — он не может отменить состоявшуюся утечку.
